Plugin reference

Each file is rendered by the first plugin that accepts it. Order matters: specific formats are tried before code, whose lexers accept almost any extension, and plain text is the catch-all.

PluginHandlesViewsAnchor
markdown.md, .markdownRendered, Sourceline
json.jsonRaw, Formattedline
csv.csv (comma-separated only)Table, Sourcecell
codeAnything chroma has a lexer forHighlighted sourceline
plaintextEverything elseTextline

Anchors

  • line: a start and end line. Gloss stores a few lines of context either side so it can follow the text when the file changes.
  • cell: the CSV record's line span, a column, and the column's header. After an edit, the column is found again by header text. If the header is gone the thread orphans.

Limits

  • Files over 1 MB fall back to plain text.
  • Binary files are shown as a placeholder.
  • Raw HTML inside markdown is stripped, not rendered.
  • Tab-separated files render as text.
  • Image, audio, video and PDF annotation are not available yet.

Writing a plugin

Plugins live in internal/plugins/ and implement a small interface that returns one or more named HTML views. Line-addressable output follows the data-line attribute convention, which gives selection, highlighting, re-anchoring and MCP support for free. The repository's /new-plugin command scaffolds the renderer, tests and fixtures. See the checklist.
